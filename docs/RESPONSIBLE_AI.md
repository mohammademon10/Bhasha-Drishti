# Responsible AI, Privacy & Safety

## Deaf-first governance
BdSL is a language, not a universal set of hand poses. Deaf/BdSL users must participate in vocabulary selection, clip review, UX and evaluation. A hearing developer's intuition is not linguistic validation.

## Consent and media
For every clip explain purpose, audience, retention, model-training and commercial use; obtain accessible informed consent; agree attribution/anonymity and withdrawal terms. No social-media scraping without permission.

## Privacy
Camera access only after user action; process locally where possible; send landmarks rather than frames; no raw media retention by default; no face identification; no unnecessary accounts/analytics/location. Protect landmarks as potentially sensitive when linkable.

## Fairness
Use held-out signers; test view, lighting, occlusion and left/right variation where data supports it. Report class imbalance and limitations. Do not infer identity or disability from camera.

## Transparency
Show supported vocabulary, model version, confidence/unknown state, data source and limitations. Clearly label reverse output as a recorded clip, not AI-generated sign.

## Safety boundaries
Never use as sole channel for diagnosis, emergency triage, informed consent, legal testimony, police questioning, financial authorization or high-stakes assessment. Human interpreter/access channel remains available.

## Error handling
Validation-selected threshold; abstain; allow correction; don't chain uncertain predictions into a sentence; disable affected class if harmful errors emerge.

## Accessibility
High contrast, scalable text, captions, keyboard operation, visible focus, non-colour-only status, large controls, reduced motion and screen-reader support.

## Compliance evidence
Dataset terms, consent, AI tools/models list, model card, evaluation report, limitations, external contribution disclosure, privacy notice and incident log.
